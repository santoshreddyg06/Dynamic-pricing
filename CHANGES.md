# Changelog: Improved EDA, Honest Metrics & Diagnostics

This document lists everything changed on the `improved-eda-honest-metrics` branch and explains why. All numbers come from executing `dynamic_pricing_notebook_improved.ipynb` end to end on the full Kaggle dataset (693,071 rows → 637,976 priced rides), using an 80/20 split with `random_state=42`.

---

## 2. Bug fixes

- **`recommend_fare` crash.** It contained `if scaler is None: scaler = scaler`, which raises `UnboundLocalError` whenever the scaler is not passed in. It now falls back to the fitted module-level scaler.
- **Arbitrary price range.** The fixed ±10% band is replaced, in the improved notebook, by an **empirical 80% prediction interval per service class**, built from the champion model's 10th/90th-percentile test residuals.
- **Duplicate `dropna`** in the feature-engineering cell removed (prices were already dropped in Cell 4).
- **`train_models.py`** now cross-validates all four models (see §1).

## 3. New notebook: `dynamic_pricing_notebook_improved.ipynb`

The original notebook is unchanged. The improved notebook keeps every original cell and adds the following sections. It is committed **with all outputs**, so the charts can be viewed without re-running it.

| Section | What it adds |
|---|---|
| 2b Data quality audit | Duplicates (0); constant columns (`timezone`); where prices are missing (all 55,095 are Uber *Taxi*); column cardinality; records per date, showing a 17-date scrape with gaps |
| 4b Target deep-dive | Skew/kurtosis, log-price histogram, Q-Q plot, within-class IQR outliers, inspection of the most expensive rides (all Lux Black XL at 2× surge, so they are real, not errors) |
| 4c Tariff reverse-engineering | Base fare + per-mile rate fitted per service class, with one small chart per class. Shows WAV ≡ UberX and Lyft's discrete price ladder |

| 5b Hour × weekday | Heatmaps of mean fare, record count and surge rate; quantifies the hourly swing (0.74%) |

| 7b Weather, controlled | Collinearity clustermap of 24 weather columns; correlation of each feature with the residual after tariff × surge; Kruskal-Wallis test with effect size within UberX |
| 8b Mutual information | Non-linear relevance of all 27 features |
| 9b Baselines | Service-class median, and the per-class tariff formula (R² 0.959) |
| 10b Fair linear model | One-hot class with class × distance / class × surge interactions (R² 0.52 → 0.96) |

Charts now use one consistent palette that is safe for colour-blind viewers: Uber is always blue and Lyft always orange, and rainbow colormaps are gone. Large intermediate frames are freed once the EDA is done, to reduce peak memory.

## 4. Headline findings (details in README → Key Findings)

1. Price is almost a formula: `(base_class + rate_class × distance) × surge` gives R² 0.959. ML improves RMSE from \$1.89 to \$1.65.
2. Hour of day and weather have no measurable effect on price. Dropping all 21 weather and time features slightly *improves* XGBoost (R² 0.9691 vs 0.9688).
3. Only Lyft surges. Surge is driven by location (Back Bay 11.2% vs North End 1.5%), not by rush hour or rain.
4. Lyft is cheaper in the Shared, Standard and XL tiers; Uber is cheaper in the Premium tiers.
5. The rule-based surge advice in the recommender (peak hours / bad weather) is not supported by this data.

## 6. How it was run

- Python 3.14 virtual environment with pandas 3.1, scikit-learn 1.9, XGBoost 3.4 and seaborn 0.13.
- Executed headless with `jupyter nbconvert --execute`.
- The original notebook was re-run as well and reproduced the previous `model_metrics.json` test metrics exactly (XGBoost R² 0.9688), which confirms the comparison is like-for-like.
- After the final full run, two cells (the CV chart and the partial-dependence chart) received display-only fixes. Rather than repeat the full run, they were re-executed against the identical model state. The CV scores reproduced exactly, and nothing else changed.
